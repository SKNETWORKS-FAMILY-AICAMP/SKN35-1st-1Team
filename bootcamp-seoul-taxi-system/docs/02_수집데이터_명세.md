## 2. 수집 방식

### 2.1 게시판형 FAQ — BeautifulSoup 2단계 크롤링

`crawler/faq_board_bs4.py`

| 단계 | 대상 | 파싱 규칙 |
|---|---|---|
| 1단계 목록 | `bbsMsgList.do?bcd=faq` | `#contents dl` 반복 → `dt > a`(질문), `dd`(요약 답변), href의 `msg_seq` 추출 |
| 2단계 상세 | `bbsMsgDetail.do?msg_seq=N` | `#contents table`에서 `th`↔`td` 쌍으로 메타데이터, `td[colspan=4]`에서 전체 답변 |

**해결한 문제** 답변에 표(장애유형별 단독탑승 기준)가 중첩된 게시글은 행 구조가
어긋나 '행 단위'로 본문을 찾으면 59자만 잡혔다. 행이 아니라 `colspan` 속성으로
본문 셀을 직접 지목해 635자 전문을 확보했다.

### 2.2 안내 페이지 → Q&A 재구성 — BeautifulSoup

`crawler/guide_pages_bs4.py`

- 본문은 `<h4>` 소제목 단위로 구성됨 → **소제목 1개 = FAQ 1건**
- 답변 = 해당 `h4` 이후 다음 `h3`/`h4` 직전까지의 형제 노드 텍스트
- 질문 문장 생성
  - 사전 정의 템플릿 우선 (`이용대상` → "장애인콜택시는 누가 이용할 수 있나요?")
  - 템플릿이 없으면 한글 **받침 유무로 조사(은/는)를 판정**해 자동 생성
- 본문 40자 미만 섹션(이미지 캡션 등)은 제외

### 2.3 동적 아코디언 — Selenium

`crawler/faq_board_selenium.py`

자주하는질문 페이지의 답변(`<dd>`)은 `display:none` 상태로 JavaScript 토글된다.
Chrome headless로 접속해 질문을 순서대로 클릭하고, 화면에 실제 렌더링된 답변을
수집한다. 목적은 **BeautifulSoup 수집 결과와의 교차검증**이다.

## 3. 전처리 파이프라인

`preprocess/build_faq_dataset.py`

| STEP | 처리 | 결과 |
|---|---|---|
| 1 | 원본 JSON 3종 로드 | 게시판 8건 + 안내페이지 34섹션 |
| 2 | 텍스트 정규화 | HTML 엔티티 복원, `\xa0`·중복 공백·3줄 이상 개행 정리 |
| 3 | 섹션 병합 | 앱접수 화면설명 **22건 → 1건** (절차 안내로 통합) |
| 4 | 결측·이상치 제거 | 답변 30자 미만 제외 |
| 5 | 중복 제거 | `content_hash`(MD5) + 정규화 질문키 기준 |
| 6 | 카테고리 자동분류 | 규칙 기반 7종 분류 |
| 7 | 키워드 추출 | 조사 제거 후 빈도 상위 5개 |
| 8 | 교차검증 | BS4 vs Selenium 대조 |
| 9 | 저장 | 정제 CSV 3종 + 품질 리포트 |

### 3.1 질문 정규화 규칙

공백·개행을 정리하고 끝의 마침표를 제거한 뒤, **의문형 어미**(`~나요`, `~가요`,
`~는지`, `무엇`, `어디` 등)로 끝나는 문장에만 물음표를 붙인다.
`~알고 싶습니다` 같은 평서형 게시판 제목에는 물음표를 붙이지 않는다.

### 3.2 카테고리 분류 규칙

카테고리별 키워드 적중 수를 **점수로 집계해 최고점을 채택**한다.
'먼저 일치하는 규칙 채택' 방식은 규칙 순서에 결과가 좌우되기 때문이다.
주제를 가장 잘 나타내는 것은 질문이므로 **질문으로 먼저 판정**하고,
질문에서 아무 규칙도 걸리지 않을 때만 본문 앞 300자로 재판정한다.

> **키워드 선정 시 주의** `콜`은 모든 문서에 있는 `장애인콜택시`에 걸려
> 21건 중 13건을 한 분류로 몰아버렸다. `이용`도 마찬가지다.
> 변별력 없는 토큰은 분류 키워드에서 제외했다.

우선순위: **① 내용 기반 규칙 → ② 출처 페이지 힌트 → ③ 기본값(준수사항·기타)**
한 페이지 안에 서로 다른 주제의 섹션이 섞여 있어(이용기준 페이지의 '이용요금' 섹션)
페이지 힌트를 우선하면 오분류된다.

### 5.4 교차검증 (BeautifulSoup vs Selenium)

게시판 8건 전부 대조, **앞부분 평균 유사도 0.968**.

| 질문 | BS4(상세) | Selenium(목록) |
|---|---|---|
| 처음 이용하는 경우 신청 방법 | 423자 | 335자 |
| 이용자격 | 635자 | 319자 |
| 운전원 취업 | 641자 | 328자 |
| 접수방법 | 594자 | 358자 |
| 운행지역 | 306자 | 306자 |

**결론** 두 방식의 답변 앞부분은 사실상 동일(유사도 0.97)하나, 목록 아코디언은
답변이 축약되어 있고 상세 페이지가 전문을 담고 있다.
→ **최종 적재는 BeautifulSoup 상세 수집본을 채택**하고, Selenium 결과는
수집 정확성 검증 용도로만 사용한다.

## 6. 수집 시 준수사항

- 요청 간 **0.7초 지연**을 두어 서버 부하를 방지했다. (`config.REQUEST_DELAY_SEC`)
- 실패 시 최대 3회 재시도하며 대기 시간을 늘린다. (2초 → 4초 → 6초)
- 공개된 안내 페이지만 수집하며, 로그인·개인정보 영역은 수집하지 않는다.
- 수집 데이터는 공공기관 공개 정보로, 학습용 팀 프로젝트 범위에서만 사용한다.
